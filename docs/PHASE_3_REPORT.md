## Privacy and security

Cookies contain 256-bit random tokens, marked HttpOnly, SameSite=Strict and Secure outside local HTTP loopback. Only SHA-256 hashes are stored. Session access expires after 30 days; browser-cookie loss prevents recovery. Expiry alone does not delete stored fields; profile deletion explicitly removes fields and the session. No account recovery is offered in this phase.

Mutations require `X-Noka-CSRF: 1`; cross-site fetches and mismatched Origin headers are rejected. Production should set `PUBLIC_ORIGIN` to its exact HTTPS origin. No cross-origin credential access is enabled. Anonymous identifiers in URLs do not authorize access.

Uploads enforce extension, MIME, magic bytes and 5 MiB. A bounded ASGI reader caps total request bytes, including chunked requests. Multipart processing may use temporary spooling; originals are closed/discarded after parsing and are never saved as application records. Parsing runs in a child process with a 10-second deadline and 512 MiB OS memory limit (Windows Job Object or POSIX address-space limit). Parser output is capped at 20,000 characters. PDF limit: 50 pages, unencrypted text documents; no OCR. DOCX limits: 300 zip entries, 20 MiB expanded content, compression ratio cap; macros, entities and external templates/content are rejected. Hyperlinks are treated as text relationships and never fetched. Documents are never executed.

Extraction proposals and evidence excerpts are transient browser/request state. **Only user-confirmed canonical skill IDs, self-rated levels, optional years, location, role interests and demo status are persisted.** Original retention is not offered. No resume is sent to Tavily or another search provider. Access logs are disabled; exception handlers log only exception classes, never bodies/provider errors. Contact-pattern redaction is best effort, not full anonymization: names may remain in text sent to OpenAI after opt-in.

OpenAI uses `responses.parse` with strict Pydantic `ExtractedSkills`/`SkillMention`, nullable bounded years, short evidence excerpts and qualitative low/medium/high confidence. `store=False`, bounded timeout and no automatic retries. Missing key, refusal, malformed/partial invalid output, or provider/network failures return local/manual review. A returned excerpt that is not in supplied text is removed. Provider retention policies may still apply; this is stated before opting in. No API key was configured during verification: **a real OpenAI call was not tested**. Mocked structured output, partial output and failures were tested.

## Transparent scoring

Only O*NET role skills with importance **≥3/5** enter the denominator. For each role:

`coverage = sum(importance × self-rated level) / sum(importance)`

Levels: learning **0.25**, working **0.65**, strong **1.0**. All absent skills have level zero. `score = min(100, 100 × coverage + interest adjustment)`, where adjustment is **5 points** for an explicitly selected role and positive coverage, otherwise zero. At least three distinct confirmed canonical skills are required. Ties are deterministic by title then role ID. Years and location do not change scores because no verified experience thresholds or Malaysian demand evidence exist.

Transferable skills enter coverage once, using the same importance weights; a separate transferable coverage breakdown is descriptive. Gaps include missing and partially developed skills, sorted by importance then name. Requirements ≥4/5 are marked critical. Gap bars represent self-rated proficiency shortfall, not job-market shortage. These are heuristic skill-fit scores, not probabilities, qualifications, forecasts or hiring guarantees. They do not depend on forecasting.

Local aliases in `backend/app/skill_extraction.py` are Noka editorial **suggestions requiring individual confirmation**, not additions to the human-reviewed public graph or official O*NET equivalences. Python/JavaScript/coding suggest Programming; communication and leadership are intentionally ambiguous. Technology mentions do not establish mastery. Fuzzy matching uses a similarity threshold of 88 with an 8-point separation; nearby ambiguous matches (≥70) offer alternatives. These internal string-similarity thresholds are not extraction confidence percentages.

## Run and demo

```sh
uv sync --frozen
uv run alembic upgrade head
pnpm build
uv run python scripts/start.py
```

Open `/profile/intake`. For the file demo, tick **This is a demo profile**, choose `data/demo/demo_cv.docx`, leave optional OpenAI unchecked, and review at least three skills. Alternatively select **Manual only** and add skills yourself. For a user's own CV, leave demo unchecked. To test live AI separately, add `OPENAI_API_KEY` to the ignored `.env` and restart; never commit it. The model remains configurable with `OPENAI_MODEL`.

Relevant references: [OpenAI structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), [pypdf text extraction limitations](https://pypdf.readthedocs.io/en/stable/user/extract-text.html), [python-docx document loading](https://python-docx.readthedocs.io/en/stable/user/documents.html). Public data licensing and role mappings remain documented in [DATA_SOURCES.md](DATA_SOURCES.md).

Limitations: no OCR, account recovery, local-vacancy evidence or forecast dependency. Some complex/active documents require pasted text or manual entry. Sparse local keyword extraction is intentionally conservative. Unrecognized specific technologies can be mapped by the user to the current broad 35-skill catalogue; they are not silently invented as canonical skills. Replit public deployment and live OpenAI verification remain outstanding external checks.
